# 0007 · 分析结论生成：规则打分 + 模型写文案的混合方式

- **状态**：接受
- **日期**：2026-10-28
- **决策者**：leexgone（产品所有者），Claude Code 辅助整理

## 背景

C8：analysis 屏与盘后复盘的分析结论（`score` / `conf` / `dims` / 建议文案）由什么生成。ADR-0005 已定架构——agent + 领域工具 + Skill 模板——但打分方式在规则 / 模型 / 混合三者间未定，影响可解释性设计与 P4-T6 的 Skill 模板。

## 决定

混合：**数字归规则，文字归模型**。`score` / `dims` / `conf` 与目标价、止损、失效条件全部由领域规则函数产出（唯一实现在 `zimu-domain` + TS 共享层镜像，口径进 `docs/03` 与黄金向量测试）；agent 调领域工具取数，模型只负责结论组织、理由说明与风险自陈文案。

## 选项与取舍

- **纯规则（不选）**：连文案都由模板拼接；最稳定、零 token 成本，但结论生硬，失去「结论 / 为什么 / 怎么做」三段式的可读性——那是产品核心体验。
- **纯模型（不选）**：把行情与持仓喂给 LLM 直接产出打分与结论；不可复现、不可解释，`conf` 失去「样本内信号一致性」的含义（CLAUDE.md 安全边界明令 conf 不得变成收益承诺），打分无法进黄金向量验收。
- **混合（选）**：每个数字可回溯到 P3 公式——这正是 P4-T6 的验收标准；文案的灵活性交给模型。代价是要维护规则口径与 Skill 模板两层，且模型文案里的数字必须全部来自工具返回。

## 后果

- 打分口径遵循 P3 流程：先改 `docs/03` 与 fixtures，再改两边实现，实现之间永不对拍。
- P4-T6 的领域工具（get_quote / get_holdings / calc_discipline / simulate_trade）+ 打分规则函数是模型唯一数字来源；Skill 模板须内嵌「文案中数字必须来自工具返回、不得自行编造」的约束与免责边界。
- 若未来想让模型参与打分本身（如学习式评分），属于推翻本决策，须重开 ADR 并先回答 `conf` 如何定义。

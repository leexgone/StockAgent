# 0020 · 推送长度守卫全量归 robit：移除宿主自截层

- **状态**：接受
- **日期**：2026-11-23
- **决策者**：主人拍板（子木侧截断功能全部去掉，全依 robit 分段处理，保证信息不丢失），Claude 协作实施

## 背景

R16（robit 0.4.1）把长度守卫透明封装进 adapter 直调路径，R17（0.5.1）扩展为「内容投影 + 长度守卫」统一出站准备。P7-T8 落地问答推送时为保持「预警/摘要既有语义逐位不变」，宿主保留了 `clip_by_lines` 按行截断（Clip 形态），与 chat_push 的透传形态并存——同一推送链两套长度语义：

- 预警/摘要：宿主先截到 caps 上限（2000 字）+ `…（已截断）` 标记，adapter 守卫对 ≤cap 文本幂等直通（双保险，但微信侧 2000–6000 字区间的内容被宿主提前丢掉，本可分段送达）。
- 边缘交互：`clip_by_lines` 的省略标记追加在截断点之后，总长可达 cap+8——R16 之后这 8 字溢出不再被静默放过，微信会把它分成第二段（尾段只有标记本身），QQ 会把标记再截一刀。罕触但语义拧巴。
- robit `send_message` trait 契约已写明「实现方按 caps 强制，**调用方不应自截**」——宿主自截层与契约方向相悖。

## 决定

1. **D1 · 单一透传形态**：删除 `clip_by_lines` 与 Clip/透传双形态分叉，`push_to_bound` 成为唯一推送链——全文透传不自截。Markdown 面投影仍显式调 `prepare_markdown_for_platform`（caps 参数化），adapter 侧二次投影幂等无操作（R17）。
2. **D2 · 三类推送统一归 robit 守卫**：`alert_push` / `post_market_review_push` / `chat_push` 长度处理全由 `prepare_outbound` 按 caps 强制——微信（非编辑平台）≤3 段分段、每段独立过节流、段失败放弃余段；QQ（编辑平台）单条截断 + `…` 省略号（平台能力边界，robit 官方语义）。
3. **D3 · 闭包单源**：main.rs 推送通道闭包只收集一份（`make_channel_push`），调度器复合 pusher 与手动问答推送共享同一 `Vec<ChannelPush>`（clone 分发），`make_channel_push_passthrough` 删除。
4. **D4 · 信息完整性口径**：平台 caps 内零宿主侧丢失；微信超 3 段尾部带 `……（内容过长，已截断）` 标记、QQ 超 2000 字带省略号——**全量永远在 `alerts` / `equity_snapshots` / `chat_messages` 与 Web 可查**。推送是通知面，不是唯一存储面；「保证信息不丢失」指宿主不再提前丢内容，平台物理上限内的截断由 robit 诚实标记。

## 选项与取舍

- **保留 Clip 双形态**（否——两套长度语义、cap+8 边缘、与 trait 契约相悖；「既有语义逐位不变」是 P7-T8 当时的保守约束，robit 守卫已真机验证，约束解除）。
- **统一透传归 robit**（选——单一语义、宿主零截断代码、微信侧预警/摘要获得分段不丢内容；R16「子木不复刻分段器」拍板的自然 completion）。
- **宿主复刻分段器替代 robit**（否——R16 已拍板框架级缺口归 robit，不重复开发）。

## 后果

**正面**：长度语义单源（robit）；宿主删除 `clip_by_lines` 及双形态分叉（净删代码）；微信侧 2000–6000 字的预警批/摘要不再被宿主提前截掉；cap+8 标记溢出边缘消失。

**负面 / 接受的成本**：

- QQ 超长仍截断（编辑平台单条模型，robit 官方语义）——非回归：此前宿主也截，只是标记从 `…（已截断）` 变为 robit 的 `…`，截断点从「按行不切半行」变为 robit 边界规则。
- 微信极端爆发轮（合并批 >3 段 ≈ 6000 字）尾部仍丢，alerts 表与 Web 可查（与 ADR-0019 既有接受成本同款，阈值从 2000 放宽到 ~6000）。
- 微信长摘要/长预警批变成多段消息（段间隔 ~2s 为节流正常表现）；push_log ok=true 意味至少首段送达（R16 既有语义）。
- wechat 屏预览卡 sub 注同步改口径（「2000 字上限超长截断」→「超长自动分段」）。

**取代关系**：ADR-0017 D5 的「2000 字按行截断（不切半行）」长度条款、ADR-0019 D2 的「超长走既有 clip_by_lines」条款被本 ADR 取代；两 ADR 的核心决策（caps 参数化零硬编码通道词汇 / 轮内合并批面）继续有效。

**以后要改回来得动哪里**：channel_push.rs 恢复 `clip_by_lines` + 双形态、main.rs 恢复两份闭包收集、03 §12 推送打包/问答推送小节、02 wechat 预览卡注、WechatScreen.tsx sub 注，并置本 ADR 已取代。

# 0013 · 智能体持仓快照校正工具：初始化与定期校准

- **状态**：接受（修订 [0012](./0012-agent-ledger-write-tools.md) 的「快照校正不开放」段）
- **日期**：2026-11-08
- **决策者**：leexgone（产品所有者），Claude Code 辅助整理

## 背景

ADR-0012（同日早些时候）把持仓快照校正（ADR-0009 直接维护：`upsert_holding`/`remove_holding`）保持界面专属，理由两条：①「看到什么抄什么」的真值来源是券商界面，不在任何工具返回值里，模型只能编；② 校正路径刻意跳过 lot/涨跌停/现金校验（「校正不是委托」），直写通道无安全网。

用户同日再拍板**放开**，依据两个新事实：

1. **初始化要能走智能体**：老账户把券商存量持仓搬进系统（ADR-0009 场景①「初始化映射」）在对话形态下同样成立——IM 场景（手机 QQ）根本没有界面，助理形态名存实亡的问题与交易录入同构；
2. **定期校准是常态需求**：系统不对接交易系统（ADR-0012 准则），持仓快照与券商真值天然存在漂移（场外变动、漏录、录错），需要**周期性校正**——这不是异常操作，是无对接架构的固有维护面。

## 决定

新增两个领域工具（三通道共享，薄封装 store 同名方法，**03 §13 口径零改动**）：

1. **`upsert_holding`**：整行覆盖 upsert（新建/编辑持仓行）。既有语义全部沿用：三不动（现金、`trades` 流水、已实现盈亏）、允许奇零股、跳过 lot/涨跌停校验、`price`/`prev` 行情字段不可改（归刷新链）、`holding_edits` 同事务留痕（op + before/after 行快照 + note）、幂等（与现值逐位一致 → 不写库不留痕）。
2. **`remove_holding`**：删除持仓行。流水保留、累计已实现盈亏不回滚、现金不动；留痕 op=delete + before 行快照。

**门禁沿用 ADR-0012 拍板（自动落账 + 读回）**，追加两条纪律：

- **整行覆盖纪律**（人格 + 工具 description 双写）：upsert 前先 `get_holdings` 读现值，只改用户明示的字段、其余原样带回——省略即丢失（sector 留空会清掉行业）；
- **删除对话内两步确认**（人格纪律）：向用户复述将被删除的整行（代码/名称/股数/成本）并得到明确同意后才调用——对应界面删除的两步确认交互；软门禁（约束模型行为），非框架硬门禁。

来源标记同 `record_trade`：note 工具层自动追加「（经智能体录入）」，进 `holding_edits` 留痕（`remove_holding` 的删除留痕无 note 入参——store 既有形状，审计靠 op=delete + before 行快照，对话侧另有会话档案 tool 行）。

## 选项与取舍

- **A · 放开 + 对话内两步确认（选）**：初始化/校准是纯助理形态的核心场景；审计面完备——`holding_edits` 的 before/after 行快照使任何误校正**可恢复**（照 before 再 upsert 一次即回滚），删除保留流水、损失有界；幂等语义天然防重复提交。0012 的两条顾虑由纪律承接：「无真值来源」→「数字必来自用户明示、缺项先问不猜」（与 record_trade 同款人格纪律）；「无安全网」→ 留痕可恢复 + 对话两步 + 幂等。
- **B · remove_holding 单独上框架硬门禁（requires_confirmation=true）（不选）**：机制三端健在，但 Web 端 confirm 无超时——用户刷新/关闭页面会无限期冻结 agent 循环（07 C13 洞①未补）；且与 0012「自动落账」拍板不一致，两种门禁风格并存易混淆。C13 补齐后可整体评估翻转（届时五个写工具一起翻，不只删除）。
- **C · 维持界面专属（不选）**：即 0012 原决定，被上述两个新事实推翻。

## 后果

- 工具面 12 → 14 注册（13 领域 + echo）；写账本五件 = record_trade / adjust_cash / get_trades（0012）+ upsert_holding / remove_holding（本 ADR）。
- 人格边界段补快照校正纪律（整行覆盖先读后改、删除两步、三不动如实说明、场外变动场景）；persona_asset 守护断言追加。
- ADR-0012「快照校正不开放」段由本 ADR 修订（0012 正文是历史记录不改，状态头加指针）。
- 界面三入口（直接录入/编辑/删除）**保持不变**：两个入口并存、同一 store 路径、`holding_edits` 互见留痕——界面「维护记录」卡会如实展示智能体写入的校正行（note 带来源标记可分辨）。
- 07 C12（现金校正留痕表）/C13（硬门禁前置补丁）维持 open，本 ADR 不改变它们。

# 0004 · 演示样本固定在 `ZM` 契约后面

- **状态**：接受
- **日期**：2026-10-24
- **决策者**：Steven Lee

## 背景

原型所有数字来自 `design/assets/data.js` 的样本：持仓行情是写死的基准值 + 确定性随机游走（`seed`/`rng`/`walk`，`data.js:11`）生成的走势，建议结论是手写文案。因为技术栈与行情源都还没定（`0003`），现在接真实数据只会把「数据形状」这个未定项提前钉死，而且免费行情源的字段名、更新频率、停牌与退市处理会反过来污染界面逻辑。

## 决定

暂时全用 mock 样本，但把边界固定成契约：页面只读 `window.ZM`，样本生成只发生在 `data.js`。将来接真实源时**只替换 `data.js` 里的原始数据产出**，页面逻辑不动（详见 `04-data-contract.md`）。

## 选项与取舍

- **A：mock + 固定契约（选）**。真实源以「可替换适配器」的形式排在 P3，届时再选 akshare / baostock / Tushare。
- **B：现在就接免费行情源（不选）**。能让演示更可信，但会让数据形状跟着源的字段名走，而且当日实时性、交易日历、复权口径这些坑会在界面层反复出现。
- **C：用随机数完全临场生成（不选）**。现有 `walk()` 是**确定性**的（同一标的每次渲染同一条曲线），这对「同一个数字在不同页面必须相等」的验证至关重要，不能改成真随机。

## 后果

- 正面：界面验证不受外部源影响，断网可跑，评审时数字稳定可复现。
- 负面与代价：
  - 样本里的业务细节是**编的**（`000832.SH` 中证转债点位、各标的四维分数、`2026-10-24` 锚定的净值起点）。文档必须写清哪些是样本、哪些是规则，否则将来会把样本当需求实现——`03` 与 `04` 已按这个原则分写。
  - 行情跳动不重算汇总（`07-backlog.md` B1）——这是 mock 阶段遗留，接真实源前必须补 `recalc()`。
  - `advice` 文案里写死的百分比靠正则覆盖（B6），是样本阶段允许的取巧，**不允许带进真实数据阶段**。
- 安全边界：样本数据不得替换成任何真实账户持仓后提交；`localStorage` 里的推送参数（AppID/Token/Webhook）在服务端落地后必须迁走。

关联：`0003`、`04-data-contract.md`、`07-backlog.md` B1/B6。

# 0012 · 智能体写账本工具面：自动落账 + 读回，流水只增不改

- **状态**：接受（「快照校正不开放」段由 [0013](./0013-agent-holding-snapshot-tools.md) 修订）
- **日期**：2026-11-08
- **决策者**：leexgone（产品所有者），Claude Code 辅助整理

## 背景

系统准则重定（2026-11-08，用户拍板）：

> 这套系统只是一套股票账户信息的维护系统，用于进行相关的分析工作；系统不会对接
> 实际的交易系统，可以理解只是一份账户信息快照。

这条准则改变了既有边界的性质。原边界「录入走界面/API 由用户确认，工具面**没有** record_trade/下单类工具」（`zimu-agent/src/tools/mod.rs` 头注释；CLAUDE.md「程序只给建议，不代下单」）建立在「写操作是危险动作、必须人在界面上按」的预设上——当系统物理上不存在任何交易通道时，「下单」从能力问题变成**表述问题**：所有录入（包括前端抽屉）本来就都是向快照账本记账。而 IM 场景（QQ 已接通、微信在途）根本没有界面，助理替主人记一笔账是 OpenClaw 式个人助理的核心形态（ADR-0011 定位）。ADR-0011 §「嘴不同手相同」同时规定：工具面按通道扩权必须是**显式新决策**——本 ADR 就是那份决策。

## 决定

给智能体（Web / QQ / CLI 三通道共享工具面，一处放开全开）新增三个领域工具：

1. **`record_trade`**（写账本）：记录一笔**已成交**的买卖——薄封装 `store.record_trade`（zimu-store 既有事务：03 §1–§4 全量校验 + 改持仓 + 写 `trades` + 联动现金），工具层零新口径。来源标记：note 自动追加「（经智能体录入）」（流水从此混合来源：界面 / 智能体 / 将来的 CSV，note 是唯一免费留痕位）。
2. **`adjust_cash`**（写账本）：把可用现金**校正到用户明示的绝对值**（`update_account` cash 语义，负数拒绝）。绝对值而非增量：增量口径逼模型心算 before+delta，违反人格「严禁自行推算」纪律；绝对值让「变动后余额」由人眼直接核对。返回 before/after/delta（delta 后端算）。
3. **`get_trades`**（只读）：查成交流水（缺省 20 条、上限 50，对话侧省 context），用于核对既往成交与定位要冲正的原笔。

**门禁 = 自动落账 + 读回**（用户拍板）：`requires_confirmation()` 保持 false，写入直接提交，agent 必须在回复中宣读完整收据（时间/标的/方向/量/价/费用三分项/变动后现金与持仓）供当场核对。防线三层：

- **store 域校验**（既有）：整手/可卖、涨跌停、现金不足、负现金——幻觉的量价形状问题在事务前被拒；
- **人格纪律**（agent.md 重写）：记账数字必须来自用户明示、缺项先问不猜、先 `simulate_trade` 试算复述再落账、落账后宣读收据；
- **事后冲正**：`trades` 只增不改（全仓无 UPDATE/DELETE 流水路径，审计账本语义），录错的出路 = 反向一笔冲正（note 互相引用「冲正 #原 id」），冲正的双费用失真如实说明、不许诺「和没错过一样」。

**「永不代下单」重定性**：从能力边界降级为**表述纪律**——任何场景不得让用户误以为系统能真实执行交易；真实操作永远发生在券商端。该短语在人格与界面文案中保留（守护测试断言不变）。

**快照校正不开放**：`upsert_holding`/`remove_holding`（ADR-0009 直接维护）保持界面专属——「看到什么抄什么」的数据源是券商界面，不在任何工具返回值里；校正无试算语义，直写通道对模型开放等于取消 human-in-the-loop。

## 选项与取舍

- **A · 自动落账 + 读回（选）**：符合纯助理形态（说记就记），域校验 + 读回 + 冲正已覆盖主要风险。代价：模型被话术诱导记账的残余风险存在——人格「数字必来自用户明示」是第一防线，绑定白名单（ADR-0011）是 IM 侧的准入闸。
- **B · 逐笔人工确认（不选，机制健在可一行翻回）**：三端确认回路已源码级核实——Web `POST /api/chat/confirm` → `WebBridge::resolve_confirm`（responder drop 按拒绝）、QQ robit-chatbot `Confirmer`（缺省关键词「确认/取消…」+ 60s 超时拒绝）、CLI 提示 [Y/n]。翻回只需三个工具 `requires_confirmation()` 返回 true。**启用前须先补两个已知洞**：Web confirm 无超时，刷新/关闭页面会冻结 agent 循环（需宿主接 `reject_pending_confirms` 或超时策略）；QQ 关键词是整句全等匹配且答非关键词当普通消息注入，绑定会话内诱导批准的注入成本低。
- **C · 开放流水删改（不选）**：`trades` 是审计基底，删改面会把账本退化为变更日志（ADR-0009 同款理由的流水版）；冲正语义足够表达更正需求。
- **D · 维持界面专属录入（不选）**：新准则下失去前提；IM 场景无界面，助理形态名存实亡。

## 后果

- 工具面 9 → 12 注册（11 领域 + echo）；`tools/mod.rs` 头注释「没有 record_trade」句删除，改写为**写账本三纪律**（数字来自用户明示、先试算后落账并宣读收据、错账只冲正不删改）。计数口径在 CLAUDE.md / backend README / assembly.rs / agent_bridge.rs / CLI 注释同步（此前「8 个领域工具」「9 领域工具」两说不齐，一并统一为「11 领域 + echo」）。
- 人格 `backend/.robit/prompts/agent.md` 边界段整段重写为账房纪律；「永不代下单 / 不是胜率 / 失效条件」三句逐字保留（persona_asset 守护断言零改动通过），断言追加「只增不改」「record_trade」两条新纪律。
- 03 手册加文首术语注 + 两处边界句 reword；数字口径（§1–§4 校验序、§13 三不动）一字不动。
- **现金校正无审计留痕表**（持仓侧有 `holding_edits`，现金侧没有）：本轮以工具返回的 before/after 进会话档案 tool 行作最低痕迹；正式方案（`cash_edits` 表）记 07 backlog 候选。
- 多通道同时生效：QQ 绑定会话即获得记账能力——绑定表仍是 IM 信任边界的唯一闸（ADR-0011），本决策不改变它。
- ADR-0011 的工具面计数与「无录入类工具」表述由本 ADR 修订（0011 正文是历史记录不改，状态头加指针）。

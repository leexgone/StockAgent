# 0009 · 持仓直接维护：快照校正与交易流水互补

- **状态**：接受（智能体快照校正入口由 [0013](./0013-agent-holding-snapshot-tools.md) 增补，界面三入口不变）
- **日期**：2026-11-01
- **决策者**：leexgone（产品所有者），Claude Code 辅助整理

## 背景

系统此前只有一条持仓变动路径：买/卖交易录入（ADR-0006 手工逐笔，事件流语义——费用、已实现盈亏、现金联动、`trades` 留档）。但真实使用存在三类**不经过买卖**的持仓变动需求：① 初始化映射——老账户把券商存量持仓搬进来，不可能也不应该回放历史每笔交易；② 纠错——数量/成本录错要能直接改；③ 场外变动——退市、债转股、红利零股。交易路径无法表达它们（伪造一笔零费用交易会把费用与已实现盈亏的审计口径搞脏）。用户明确提出需要直接增、删、改持仓的方式。

## 决定

新增**持仓直接维护**入口（`PUT /api/holdings/{code}` upsert + `DELETE /api/holdings/{code}`），定位为**快照校正**，与交易录入互补、不互相替代。口径全文见 `03` §13，要点：

- 调整 = 整行覆盖（「看到什么抄什么」），cost 修改不产生已实现盈亏；
- **现金不联动**（用户拍板）：现金由既有「可用现金 · 调整」单独校正，避免初始化双重扣款；
- **不写 `trades`**，审计痕走新表 `holding_edits`（schema v3：op + before/after 行快照 + note，与持仓写入同事务）；前端持仓屏增「维护记录」卡露出（用户拍板）；
- 允许奇零股（shares ≥ 1 任意整数）；跳过 lot 与涨跌停校验（校正不是委托）；price/prev 不可编辑（行情字段归刷新链）；
- 删除整行、流水保留、累计已实现不回滚——界面如实说明连续性断开。

## 选项与取舍

- **直接维护 + 独立编辑留痕（选）**：语义干净——事件流归 `trades`、快照校正归 `holding_edits`，两边审计都不被污染；实现小（两端点一表一迁移）。代价：流水与持仓的连续性在校正点断开，需文案如实披露。
- **合成零费用调整交易进 `trades`（不选）**：流水「完整」但造假——费用合计、已实现盈亏、成交均价全部被非交易事件污染，`trades` 从审计账本退化为变更日志。
- **只允许删除+重录（不选）**：纠错成本转嫁给用户，且重录会丢行情回写字段的历史，删除+重录两步之间派生数字闪变。

## 后果

- `zimu-store` schema v3（`holding_edits` 表 + upsert/remove/编辑痕事务方法）；`zimu-server` 两端点 + `GET /api/holding_edits`（维护记录卡数据源）进 OpenAPI 契约。
- 前端持仓屏：行内「编辑 / 删除」（两步确认）+ 页头「直接录入」（新建）+「维护记录」卡；编辑表单与 B15 手工新标的字段同形状，但无试算预览（校正没有试算语义）。
- recalc 派生零特判（§5 从 holdings 现值现算），调度/诊断/建议链路无感知。
- CSV 批量导入仍是独立后续增强（ADR-0006），届时复用本 ADR 的 upsert 语义与编辑留痕。

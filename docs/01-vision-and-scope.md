# 01 · 产品定位与范围

## 一句话

子木是**一个人用的股票助理**：替你盯着持仓、解释发生了什么、给出可以照着执行的建议，并且把结论送到你手机上。

它不是券商软件（不能下单），不是量化平台（不做策略回测），也不是资讯 App（不做泛行情推送）。它围绕**你自己的组合**工作，所有回答都要能落回「你的持仓怎么办」。

## 目标用户

- 单用户、单券商账户、只投沪深市场
- 有持仓、有浮亏浮盈、需要纪律而不是情绪的人
- 会看基本面也看技术面，但没时间盯盘；盘中靠预警，盘后靠复盘

## 一天的使用场景

| 时段 | 助理做的事 | 对应界面 |
|---|---|---|
| 08:30 盘前 | 要闻与持仓相关度筛选，生成当日关注点 | 微信推送 / 工作台 |
| 盘中 | 价格条件、放量、止盈止损线监控，触发即推送 | 总览（待处理预警）、微信 |
| 15:05 盘后 | 收盘摘要：谁在拖谁在拉、今日盈亏归因、明日观察 | 总览、微信 |
| 晚上 | 想问就问：「比亚迪要不要止损」，回答带依据与操作步骤 | 智能问答 |
| 周末/事件驱动 | 组合体检：集中度、回撤、再平衡清单 | 组合诊断 |

## 范围内

- 标的：A 股普通股、场内 ETF、可转债（`kind: stock | etf | cb`）
- 持仓：明细、加减仓**试算**（摊薄成本、费用、仓位重算）、成交流水
- 行情：指数快照、市场时钟（集合竞价/早盘/午间休市/午盘/盘后定价/休市）
- 分析：综合得分 + 结论标签 + 置信度，技术面/基本面/资金面/消息面四维拆解，目标区间与止损，分笔执行计划，历史建议留档
- 问答：结论 / 为什么 / 怎么做三层结构，每条回答附可回溯的依据来源
- 诊断：波动率、最大回撤、夏普、胜率、行业集中度与 HHI、分区间对比、再平衡建议及调整前后波动测算
- 推送：6 类订阅（预警/复盘/建议确认/问答回复/期限提醒/系统降级）、推送时段、静音标的、通道降级

## 明确不做

| 不做 | 原因 |
|---|---|
| 港股、美股、场外基金 | 交易单位、费用、涨跌停口径完全不同，先做透一个市场 |
| 登录、多用户、权限、云端账户 | 定位是个人本地工具，加了就不是一个人能维护的东西 |
| 连接券商接口、代提交委托 | 合规与资金安全红线；加减仓只是本地试算，成交由你在券商 App 完成 |
| 自动跟投、策略回测、实盘信号 | 那是另一个产品；这里给的是「建议 + 你自己决定」 |
| 收益预测、胜率承诺 | `conf` 只表示样本内信号一致性，不是胜率（见 `analysis.html` 文案） |

## 责任与合规边界

这几条在原型里已经落地为具体界面元素，后续开发不能删：

1. **每屏都有免责区块**（`dashboard.html#dash-disclaimer`、`index.html#home-disclaimer` 等），说明数据是演示样本、建议不构成投资意见。
2. **每条建议必须自带风险自陈**：`advice[code].risks[]` 至少一条，说明「这个结论可能错在哪」。
3. **每个结论给可执行边界**：目标价区间 + 止损价 + 失效条件，不给「必涨」「稳赚」这类表述。
4. **真实数据接入后仍需人确认每一笔**：`holdings.html` 抽屉里有「我已确认这笔委托」勾选（`#confirm-flag`），未勾选不能提交，这是刻意设计。
5. **个人持仓是敏感数据**：默认不上传第三方；示例数据不能替换成真实账户持仓后提交进仓库。

## 原型阶段的成功标准

- 信息架构定稿：七个界面各自职责清楚，没有「这块数据从哪来」的悬空问题
- 交互闭环验证：从「预警 → 看建议 → 去持仓页试算 → 记下要买/卖」走通（`analysis.html` 的「送到持仓页试算」已实现）
- 口径自洽：任何两处出现的同一个数字必须相等
- 业务规则可复述：`docs/03-domain-rules.md` 里的公式能被后端原样实现

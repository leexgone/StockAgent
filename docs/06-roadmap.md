# 06 · 路线图

原则：**先在原型里把产品想清楚，再决定用什么写后端。** 每阶段都有「完成标准」，达不到就不进下一阶段——不要靠新增依赖来掩盖没做完的事。

## P0 · 工程与文档基线 ✅ 本轮

**做**：仓库卫生（`.gitignore` / `.gitattributes` / `.editorconfig`）、根 README、CLAUDE.md、docs/ 规格与口径手册、ADR 记录暂缓选型的决定。

**完成标准**：任何人（包括下一次的我自己）打开仓库能在 10 分钟内知道：这是什么、现在处于什么阶段、改界面前该读哪几页、哪些事明确不做。

## P1 · 原型定稿 🔨 进行中

**做**：
- 清掉 `07-backlog.md` 里的阻断项（跨页派生缺失）与口径不一致项
- 补齐交互细节：分析页的历史建议与 `advice` 关联、问答页的依据可点击跳转、诊断页再平衡逐条落地到持仓页试算
- 界面层面确认「录入第一笔持仓」的路径（现在原型是从已有持仓开始，真实用户是空的）
- `design/README.md` 与 `docs/` 内容收敛为单一来源

**完成标准**：七个界面在 `file://` 与本地服务两种方式下打开均无控制台报错；从「预警 → 建议 → 试算 → 结论」走一遍不需要离开原型；同一个数字在任意两处出现都相等。

## P2 · 口径可执行化

**做**：把 `03-domain-rules.md` 的公式抽成一组纯函数（整手、费用、摊薄、涨跌停、仓位、净值指标），仍放在 `design/assets/` 里以原生 JS 模块使用，不引入构建工具；为每条公式配一组「手算可对」的用例数字，写进文档。

**完成标准**：任何人可以用这组函数 + 一份持仓表，在纸上复算出界面上的每一个数字。这一步是后端实现的验收基线，比写测试更重要。

## P3 · 数据契约固化 + 适配器

**做**：按 `04-data-contract.md` 定义真实数据的输入形状；把 `QW` 拆成「静态样本」与「适配器」两层，加 `recalc()`；确定交易日历来源；确定时间戳与时区口径。

**完成标准**：换掉数据源不需要改任何 `.html`；行情更新后所有屏的数字仍然互相一致。

## P4 · 技术选型与代码骨架 ⏸ 待启动（受 ADR-0003 约束）

**做**：定后端栈、定前端是否框架化、建最小可运行骨架、定存储方式（本地 SQLite / 文件）、定密钥管理。

**触发条件**：P1–P3 完成，且愿意开始写服务端时。选型讨论先写进 ADR，再建目录。

## P5 · MVP 垂直切片

**做**：手工录入持仓 → 每日行情更新 → 收盘复盘与建议 → 条件预警 → 微信推送。

**完成标准**：连续 5 个交易日真实跑通，推送内容里的每个数字都能回溯到 P2 的公式。

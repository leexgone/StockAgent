# 06 · 路线图

原则：**先在原型里把产品想清楚。** 技术路线已定（ADR-0005：Rust + robit 基建 / React + Vite 前端 / Python 行情 sidecar / SQLite）。每阶段都有「完成标准」，达不到就不进下一阶段——不要靠新增依赖来掩盖没做完的事。

## P0 · 工程与文档基线 ✅ 本轮

**做**：仓库卫生（`.gitignore` / `.gitattributes` / `.editorconfig`）、根 README、CLAUDE.md、docs/ 规格与口径手册、ADR 记录暂缓选型的决定。

**完成标准**：任何人（包括下一次的我自己）打开仓库能在 10 分钟内知道：这是什么、现在处于什么阶段、改界面前该读哪几页、哪些事明确不做。

- ~~清掉阻断项 A1（跨页派生缺失）~~ 已修复，B1（行情跳动后汇总不同步）也已修复，见 `07-backlog.md`「已修复」栏；剩余：空态 A2 与口径不一致 B2–B9

## P2 · 技术基座 Spike ⏳ 待启动（ADR-0005 已定案）

**做**（四个 spike，验证 0005 的每个假设，目录随 spike 创建）：

- `backend/`：Cargo workspace，path override 指向本地 robit（`E:\Github\robit`），跑通最小 agent 会话——接阿里云网关 qwen、注册一个领域工具；**并走一遍两工程共同演进回路**：发现一个框架级缺口 → 改 robit（保持通用）→ 打 tag → 子木 pin rev 升级。
- axum 骨架：一个 REST 端点 + SSE 把 robit-agent 事件流转出来，验证流式链路。
- `datafetch/`：uv + FastAPI + akshare spike——股票/ETF/可转债/指数的真实字段、盘中频率、限频表现，产出与 `04` 契约字段的对照表（半天到一天）。
- `frontend/`：Vite + React + TS 脚手架，`ui.css` 设计令牌迁移（oklch、红涨绿跌、tabular-nums、断点），复刻 index 一屏静态版。

**完成标准**：四个 spike 全部跑通；robit 痛点已记入 `07-backlog.md` R 系列。若任何 0005 假设被证伪（robit API 不适配、akshare 拿不到转债数据等），回 ADR 修订再继续。

## P3 · 口径可执行化（黄金测试向量）

**做**：把 `03-domain-rules.md` 的每条公式（整手 / 费用 / 摊薄 / 涨跌停 / 仓位 / 净值指标 / 波动合成）落成三件东西：① 「手算可对」的用例 JSON（黄金向量，入库做共享 fixture）；② Rust 纯函数库——权威实现，推送 / 复盘 / 预警用它；③ TS 实现——抽屉试算等即时交互用。两边跑同一组 fixture。

**完成标准**：`cargo test` 与前端测试全绿；任何人可以用 fixture + 一份持仓表在纸上复算出界面上的每一个数字。

## P4 · 数据管道与存储

**做**：SQLite schema（持仓 / 建议留档（解 B9）/ 预警 / 净值快照 / 交易流水）；`datafetch` 正式接口（`/quote` `/kline` `/cb_list` `/calendar`）与 akshare→baostock 兜底逻辑；Rust 行情适配器（唯一消费入口，sidecar 挂了主程序降级不崩）；把 `04` 的 `ZM` 契约固化为 OpenAPI + serde 结构体；交易日历与时区口径；`recalc()` 的服务端等价实现。

**完成标准**：重启后端不丢持仓与留档；行情更新后 API 数字与 `03` 口径一致；换数据源实现不动 API 面。

## P5 · 前端移植

**做**：7 屏逐屏移植到 `frontend/`（组件化 + 设计令牌 + 保留 `data-od-id`），数据从 mock `ZM` 切到后端 API（含 SSE 会话流）；wechat 屏改为 PushProvider 配置管理（视 C4 进展）。

**完成标准**：与原型功能对等、控制台无报错、窄屏断点通过；`design/` 原型冻结为参照（保留不删）。

## P6 · MVP 垂直切片

**做**：手工录入持仓（**C5 需先拍板**）→ 每日行情更新 → 盘后复盘与建议（Skill + agent）→ 条件预警（盘中轮询）→ 微信/QQ 会话与推送（QQ 可先行：`robit-qq` 出站 WS 现成；微信渠道 **C4 需先拍板**，双向会话与公网回调要求见 backlog C4）。

**完成标准**：连续 5 个交易日真实跑通；推送内容里的每个数字都能回溯到 P3 的公式；每条建议带生成时间与数据版本留档。
